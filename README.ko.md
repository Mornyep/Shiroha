# 白羽 Shiroha

히로인 루트 타러 왔는데, 왜 폴더 경로부터 공략하고 있죠?

[中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · 한국어

[v0.14.0 프리뷰 다운로드](https://github.com/Mornyep/Shiroha/releases/tag/v0.14.0) · [문제 제보](https://github.com/Mornyep/Shiroha/issues) · [변경 내역](CHANGELOG.md)

Shiroha는 macOS용 비주얼 노벨 라이브러리이자 CrossOver 런처입니다. 게임, 표지, 작품 정보, 실행 설정, 수동 북마크를 책장 하나에 모아 둡니다. 오늘은 진짜 밀린 게임 좀 하려고 했는데, 실행 파일 찾다가 하루가 끝나는 건 좀 억울하잖아요.

Windows 게임은 현재 별도로 설치한 CrossOver로 실행합니다. 독립적인 호환 환경을 위한 GalBridge는 아직 연구 중입니다.

이름은 『Summer Pockets』에서 가장 좋아하는 히로인, 나루세 시로하에게서 가져왔습니다. 이름부터 최애 편애가 조금 들어갔습니다.

## 책장에 담은 기능

- **라이브러리**: 큼직한 표지, 검색, 즐겨찾기, 사용자 컬렉션. 밀린 게임 정리도 일단 진도라고 쳐 주세요.
- **추가와 실행**: EXE나 게임 폴더를 추가하고 Steam 게임을 찾습니다. 게임마다 보틀(Bottle), 실행 파일, 실행 인수를 저장할 수 있습니다.
- **작품 정보**: Steam, Bangumi, VNDB에서 작품을 찾아 연결합니다. 정보와 이미지를 직접 수정할 수도 있습니다.
- **플레이 기록**: 이름을 붙인 북마크, 수동 진행 기록, 선행 조건이 있는 공략 메모를 정리합니다. ‘이 선택지 전에 세이브’도 이제 기억력에만 맡기지 않아도 됩니다.
- **로컬 진단**: EXE와 DLL 의존성, 실행 로그를 확인합니다. AI의 요약 설명은 선택 사항이며, 보내기 전에 내용을 확인할 수 있습니다.
- **세이브 백업**: 지정한 세이브 폴더를 백업하고 파일을 검증합니다. 복원할 때는 새 폴더에 저장합니다.

라이브러리는 Mac에 저장됩니다. 광고나 텔레메트리가 없으며, 클라우드 동기화가 기본으로 켜져 있지도 않습니다. 라이브러리, 실행, 로컬 진단에는 AI 계정이 필요하지 않습니다. 온라인 작품 검색은 해당 서비스에 접속합니다. 선택형 AI 기능을 사용하면 미리 확인한 요약이 설정한 서비스로 전송됩니다.

## 설치하고 첫 실행까지

1. [v0.14.0 릴리스 페이지](https://github.com/Mornyep/Shiroha/releases/tag/v0.14.0)에서 `Shiroha-0.14.0-arm64.zip`을 받습니다. 같은 페이지에 소스 코드와 SHA-256 체크섬 파일도 있습니다.
2. ZIP을 풀고 `白羽 Shiroha.app`을 응용 프로그램 폴더로 옮깁니다.
3. CrossOver를 따로 설치하고, 정식으로 구한 게임과 해당 게임용 보틀을 준비합니다. 게임, CrossOver, Windows 구성 요소는 포함되어 있지 않습니다.
4. Shiroha에서 게임을 추가한 뒤 보틀과 실행 파일을 선택하고 실행합니다.

Apple Silicon Mac과 macOS 14 이상이 필요합니다. 현재는 arm64 패키지만 제공하며 Intel Mac은 지원하지 않습니다. 공개 버전의 검증 환경은 macOS 27.2이며, macOS 14와 15에서는 실제 기기 검증을 마치지 않았습니다. 게임 실행 여부는 CrossOver와의 호환성에 따라 달라집니다.

**앱 표시 언어**: 이 문서는 한국어 안내입니다. 현재 앱 화면은 주로 중국어로 표시됩니다. 한국어 문서가 있다고 해서 앱 UI도 한국어로 제공되는 것은 아닙니다.

프리뷰는 ad-hoc 서명을 사용하며 Apple 공증을 받지 않았습니다. 개발자를 확인할 수 없다는 메시지가 뜨면 먼저 이 저장소에서 받은 파일이 맞는지 확인해 주세요. 실행을 한 번 시도한 뒤 시스템 설정 → 개인정보 보호 및 보안 → ‘확인 없이 열기’에서 열 수 있습니다. 시스템 보안 기능을 끌 필요는 없습니다. 악성 소프트웨어나 파일 손상 경고가 나오면 실행을 멈추고 다운로드 파일을 확인해 주세요. [Apple 안내](https://support.apple.com/en-us/102445)도 참고할 수 있습니다.

### 업데이트와 삭제

이전 이름은 VNLauncher이며 기존 로컬 데이터 폴더를 그대로 사용합니다. 업데이트 전에 이전 버전을 종료하고 백업을 남겨 주세요. 같은 라이브러리를 두 버전에서 동시에 편집하지 마세요.

삭제하려면 앱을 종료하고 휴지통으로 옮기면 됩니다. 게임, CrossOver 보틀, 세이브는 지워지지 않으며 실행 중인 게임도 자동으로 종료되지 않습니다. 라이브러리는 `~/Library/Application Support/VNLauncher`에 남습니다. 이 폴더까지 지우려면 먼저 백업해 주세요. 저장한 API 키는 키체인의 `local.VNLauncher.advisor` 서비스에 남습니다.

## 아직 공략 중인 부분

- 북마크와 공략은 수동으로 정리합니다. 챕터 자동 인식이나 게임의 저장·불러오기와 연동하는 기능은 없습니다.
- 실제 게임의 음성, 영상, 입력, 저장·불러오기를 폭넓게 검증하지 못했습니다. 모든 게임의 정상 작동을 보장하지 않습니다.
- 구성 요소 설치와 롤백, 외부 Steam 라이브러리의 전체 사용 흐름은 추가 실사용 검증이 필요합니다.
- 백업 전에 게임의 세이브 쓰기를 멈춰 주세요. 실행 중인 데이터를 한 시점으로 고정하는 원자적 스냅샷은 지원하지 않습니다.

## 다음 업데이트에서는

0.15를 목표로 CrossOver 설정, Bangumi·VNDB 항목 매칭, 즐겨찾기 연동, Steam 플레이 시간 JSON 가져오기, 로컬 시간 측정을 다듬고 있습니다. 포스터 색 추출 설정도 간소화해 사용하지 않는 배경화면·디스크 이미지 항목을 없앱니다. 기존 이미지와 공통 색 추출 기능은 유지합니다. 아직 공개되지 않은 후보 버전이며 화면 조작과 실제 게임에서의 시간 측정은 검증이 남아 있습니다. **지금 받을 수 있는 버전은 v0.14.0입니다.**

루트와 세이브 인식도 연구 중입니다. 제한된 Ren'Py 스크립트, 직접 만든 샘플 세이브, 일부 경로 분석부터 진행하고 있습니다. 상용 게임의 엔딩 판별, 범용 세이브 지원, 실시간 진행 추적 기능은 아직 제공하지 않습니다. 선택지 앞 세이브는 계속 직접 해 주세요. 여기서 방심하면 또 공통 루트부터입니다.

GalBridge에는 독립 실행을 검증한 상용 게임 목록이 아직 없습니다. 누락된 구성 요소의 설치 지원과 게임별 호환성 기록도 앞으로의 과제입니다. GPTK는 검토 중이며, Godot 기반 네이티브 재구축은 더 장기적인 연구입니다. 출시일은 아직 정하지 않았습니다.

## 소스에서 빌드하기

Swift 6, SwiftUI / AppKit, Swift Package Manager를 사용하며 서드파티 Swift Package 의존성은 없습니다. 전체 Xcode 설치가 필요합니다. 저장소에 기록된 검증 도구 체인은 Xcode 27.0 / Swift 6.4입니다.

```sh
git clone https://github.com/Mornyep/Shiroha.git
cd Shiroha
# 설치된 Xcode 경로로 바꿔 주세요.
export DEVELOPER_DIR="/path/to/Xcode.app/Contents/Developer"
bash app/scripts/build.sh
bash app/scripts/test.sh
```

결과물은 `app/build/Shiroha.zip`에 생성됩니다. 스크립트가 아이콘을 만들고 ad-hoc 서명을 적용합니다. Developer ID 서명과 공증은 포함되지 않습니다.

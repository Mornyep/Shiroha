# 白羽 Shiroha

攻略したいのはヒロインのルート。exeまでの道のりじゃない。

[v0.14.0 プレビュー版をダウンロード](https://github.com/Mornyep/Shiroha/releases/tag/v0.14.0) · [不具合の報告](https://github.com/Mornyep/Shiroha/issues) · [更新履歴](CHANGELOG.ja.md)

Shirohaは、Mac用のビジュアルノベル管理アプリ兼CrossOverランチャーです。ゲーム、ジャケット画像、作品情報、起動設定、手動のしおりをひとつの本棚にまとめます。「今日は積みゲーを崩すぞ」と意気込んだのに、フォルダ探しだけで夜が終わる。そんな寄り道を少し減らすために作りました。

Windowsゲームの実行には、今のところインストール済みのCrossOverを使います。独自の互換環境を目指すGalBridgeはまだ研究中です。

名前は『Summer Pockets』で一番好きなヒロイン、鳴瀬しろはから。命名には、だいぶ私情が入っています。

## 本棚でできること

- **ゲーム管理**：大きなジャケット表示、検索、お気に入り、独自のコレクション。本棚の整理も積みゲー消化の一歩……ということにしておきましょう。
- **登録と起動**：exeやゲームフォルダの登録、Steamゲームの検出。ボトル、実行ファイル、起動引数を作品ごとに保存できます。
- **作品情報**：Steam・Bangumi・VNDBを検索して該当作品を選択。情報や画像の手動編集もできます。
- **プレイ記録**：名前付きのしおり、手動の進捗記録、前提条件付きの攻略メモ。「この選択肢の前でセーブ」を覚えておく場所に。
- **ローカル診断**：exe・DLLの依存関係や起動ログを確認。AIによる要約の説明は任意で、送信前に内容を確認できます。
- **セーブのバックアップ**：指定したセーブフォルダをバックアップしてファイルを検証。復元先は新しいフォルダになります。

ライブラリはMac内に保存されます。広告・テレメトリー・標準で有効なクラウド同期はありません。ゲーム管理、起動、ローカル診断にAIアカウントは不要です。オンラインの作品検索では各サービスに接続します。任意のAI機能を使う場合は、確認した要約を設定先のサービスに送ります。

## インストールして、まずは起動

1. [v0.14.0の公開ページ](https://github.com/Mornyep/Shiroha/releases/tag/v0.14.0)から `Shiroha-0.14.0-arm64.zip` をダウンロードします。同じページにソースコードとSHA-256チェックサムもあります。
2. ZIPを展開し、`白羽 Shiroha.app` を「アプリケーション」へ移動します。
3. CrossOverを別途インストールし、正規に入手したゲームと対応するボトルを用意します。ゲーム本体・CrossOver・Windowsコンポーネントは同梱していません。
4. Shirohaでゲームを登録し、ボトルと実行ファイルを選んで起動します。

Apple Silicon搭載MacとmacOS 14以降が必要です。配布パッケージはarm64のみで、Intel Macには現在対応していません。公開版の検証環境はmacOS 27.2で、macOS 14・15での実機動作は未検証です。各ゲームの動作はCrossOverとの互換性に依存します。

**表示言語について**：これは日本語の説明書です。アプリの画面は現在、中国語が中心です。日本語版ドキュメントの追加と、アプリの日本語対応は別のものです。

プレビュー版はad-hoc署名で、Appleの公証は受けていません。開発元を確認できないという表示が出た場合は、まずダウンロード元がこのリポジトリであることを確認してください。起動を試した後、「システム設定 → プライバシーとセキュリティ → このまま開く」から開けます。システムの保護機能を無効にする必要はありません。マルウェアやファイル破損の警告が出た場合は起動を中止し、ダウンロード内容を確認してください。[Appleの案内](https://support.apple.com/en-us/102445)も参照してください。

### 更新・アンインストール

旧名はVNLauncherで、データの保存先は引き継いでいます。更新前に旧版を終了し、バックアップを残してください。同じライブラリを複数のバージョンで同時に編集しないでください。

アンインストールは、アプリを終了してゴミ箱へ移動します。ゲーム・CrossOverのボトル・セーブは削除されず、起動中のゲームも自動終了しません。ライブラリは `~/Library/Application Support/VNLauncher` に残ります。手動で削除する場合は先にバックアップしてください。保存済みAPIキーはキーチェーンのサービス名 `local.VNLauncher.advisor` に残ります。

## まだ回収できていないところ

- しおりと攻略は手動です。章の自動認識やセーブ・ロードとの同期はありません。
- 実際のゲームでの音声・動画・入力・セーブ・ロードは網羅的に検証できていません。すべての作品の動作を保証するものではありません。
- コンポーネントのインストールとロールバック、外部Steamライブラリの一連の操作は、引き続き実機検証が必要です。
- バックアップ前にゲームの書き込みを止めてください。動作中のデータを一括で確定するアトミックスナップショットには対応していません。

## 次の更新に向けて

0.15に向けて、CrossOver設定、Bangumi・VNDBの照合、お気に入りの連動、Steamプレイ時間のJSON読み込み、ローカルでの時間計測を調整中です。ポスターからの色抽出設定も整理し、使われていない壁紙・ディスク画像の項目を削除します。既存の画像と共通の色抽出機能は残します。まだ未公開の候補版で、画面操作や実ゲームでの計測は検証が残っています。**現在ダウンロードできるのはv0.14.0です。**

ルート・セーブ認識も研究中です。対象を絞ったRen'Pyスクリプト、自作のサンプルセーブ、限られた経路の解析から進めています。市販作品のエンディング判定、汎用セーブ対応、リアルタイムの進行追跡はまだできません。選択肢前のセーブは、引き続きお忘れなく。

GalBridgeには、単独での動作を確認済みの市販ゲーム一覧はまだありません。不足コンポーネントの導入支援や作品ごとの互換性記録も今後の課題です。GPTKは検討中、Godotによるネイティブ再構築はさらに長期的な研究になります。公開日は、まだフラグを立てずにおきます。

## ソースからビルド

Swift 6、SwiftUI / AppKit、Swift Package Managerを使用しています。第三者製Swift Packageへの依存はありません。完全版のXcodeが必要です。リポジトリに記載された検証済みツールチェーンはXcode 27.0 / Swift 6.4です。

```sh
git clone https://github.com/Mornyep/Shiroha.git
cd Shiroha
# 手元のXcodeのパスに置き換えてください
export DEVELOPER_DIR="/path/to/Xcode.app/Contents/Developer"
bash app/scripts/build.sh
bash app/scripts/test.sh
```

出力先は `app/build/Shiroha.zip` です。スクリプトはアイコンを生成し、ad-hoc署名を行います。Developer ID署名・公証は含みません。

## 困ったとき・開発に参加するとき

共通ルートを最初からやり直す前に、まずはこちらを。

1. **CrossOverやボトルが見つからない**：設定でインストール済みのCrossOverを選び、ボトル一覧を更新してください。ゲーム用のボトルがCrossOver側に用意されているかも確認します。
2. **ゲームが起動しない**：実行ファイル・ボトル・起動引数を確認し、同じボトルからCrossOverで直接起動してみてください。両方の結果があると、起動設定とゲームの互換性を切り分けやすくなります。
3. **別の作品が表示される**：Steam・Bangumi・VNDBの該当作品を選び直すか、手動で編集してください。同名作品や別エディションの場合は、作品名と版も添えて報告してください。
4. **バックアップや復元に失敗する**：ゲームの書き込みを止め、元のセーブとバックアップを残してください。新しいフォルダへの復元結果を確認してから扱いを決め、唯一のコピーを上書きしないでください。

小さな修正、翻訳、互換性の報告も歓迎します。大きな変更は、先に[Issue](https://github.com/Mornyep/Shiroha/issues)で内容を相談してください。PRには変更点、確認したこと、未検証の点を書いてください。コード変更では上記のテストを実行し、文書変更では各言語のリンクを確認します。提出する権利のある内容だけを含め、既存のライセンスと第三者の権利表記を保持してください。ゲーム素材、個人情報、キー、ローカルで生成されたファイルは含めないでください。多言語の案内はありますが、言語ごとの専任サポート窓口があるわけではありません。
